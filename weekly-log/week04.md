# 4주차 · 연결하고 점검하기

날짜와 상관없이 순서대로 진행한다. 이번 주 분량은 18시간이다 (원래 15시간 + 책 8·9장 칸 3시간).

**이번 주 목표:** 웹사이트 뒤편(서버·데이터베이스), 해시와 암호화의 차이를 배우고, 지금까지 배운 것을 "웹페이지가 화면에 뜨기까지" 그림 하나로 잇는다. 사이사이에 책 8장(허위 정보)과 9장(무제한 소비)을 쓴다. 마지막 칸에서 1달차 AI 면접을 본다.

**최소 목표:** 1달차 성공 기준 두 가지를 혼자 설명할 수 있다. ① 웹페이지가 내 화면에 뜨기까지의 과정을 그림으로 그리기 ② 보안 3원칙을 실제 사고 예시로 설명하기.

**3주차에서 바꾼 것:** 노트 16~20 대신 책 2부 원고(22장부터)를 쓴다. 4-1은 11장과 겹치는 앞쪽은 빼고 서버 뒤편(웹 서버·프로그램·데이터베이스)을 중심으로 쓴다. 4-4 AI 사고 소식은 Claude가 후보 2~3개를 고른다. 4-5 ②는 노트 다시 읽기 대신 책에 남은 `[확인 필요]` 4곳(7장 3곳, 20장 1곳)을 처리하고, 면접 준비로 16장과 의료 챗봇 사례를 다시 본다. 칸마다 보는 퀴즈는 객관식을 늘리고, 4-6 ③ 'AI 설명 대조 정리'는 배운 내용 정리와 객관식 퀴즈로 바꾼다 (AI 설명 대조와 TryHackMe 개념 룸은 효과가 적어 더 하지 않음).

## 이번 주 AI 보안 소식 (4-4)

- 제목과 링크: Cline CLI npm 허락 없는 게시 사고 (2026-02) — [Cline 사후 보고서](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm), [GitHub 보안 권고 GHSA-9ppg-jx86-fqw7](https://github.com/advisories/GHSA-9ppg-jx86-fqw7), [연구자 글 'Clinejection'](https://adnanthekhan.com/posts/clinejection/)
- 무슨 일: Cline 팀이 GitHub 이슈를 AI 봇에게 분류시켰는데, 봇은 누구나 움직일 수 있었고 터미널도 쓸 수 있었다. 이슈 제목에 숨긴 지시로 봇이 남의 코드를 돌릴 수 있었고, 그 코드는 공용 캐시를 거쳐 npm 배포 열쇠를 가진 밤 작업까지 닿을 수 있었다(연구자는 앞단계만 시험 저장소에서 재현). 신고 뒤 공개까지 39일, 공개 뒤 열쇠를 바꾸다 엉뚱한 열쇠를 지워, 2026-02-17 누군가 살아 있던 열쇠로 `cline@2.3.0`을 약 8시간 올려 두었다(다른 프로그램이 함께 설치되는 한 줄)
- 3원칙으로 정리: 기밀성(배포 열쇠가 팀 밖으로 나감) → 무결성(팀이 넣지 않은 한 줄이 Cline 이름으로 배포됨). 가용성은 크게 깨지지 않음
- 어떻게 막나: AI 봇에서 터미널 빼기, 남의 글을 읽는 작업과 열쇠를 가진 작업을 나누기(캐시 공유 금지), 오래 사는 열쇠 대신 잠깐 쓰고 버리는 열쇠, 열쇠를 바꾼 뒤 화면이 아니라 실제 열쇠로 막혔는지 시험, 신고에 빨리 답하기
